0.31.1 fixes a login issue for tasks on OpenRouter models and an issue number link in todos.

## What a user notices

- **A task that has been on an OpenRouter model no longer gets logged out on Claude models (#625, PR #629).** Such a task was resumed by the Agent SDK from a temporary folder holding a copy of the Claude login that could not renew itself, so after some hours it said "logged out" although the real login was fine, and Log in did not help until Glade was restarted. Now a session of such a task on a Claude model starts the ordinary way, on the real login. Its full history is kept: Glade writes what the session file is missing before the start, and reads the file back when the task next switches to an OpenRouter model.
- **Todos: an issue number links when several links point at that issue (#626, PR #628).** A todo titled "#2283: …" showed its number as plain text when the issue and comments on it were all filed under the task. Links to the same issue or PR now count as one and the number opens the issue's own page. A number shared by different things (the same number in two repositories) still stays plain text.

## Under the hood

- No migrations.
- If the history can't be written into the session file or checked (the file can't be read, a write fails, the session's project folder isn't known), that start falls back to the old resume and logs why, so history is never dropped to save the login (#629).
- `docs/sdk-notes.md` records what was read in the SDK: a resume with a session store builds a temporary config folder and copies the login without its refresh token.

## Running it

- **Requirements:** a Mac with Apple silicon, logged in to [Claude Code](https://docs.claude.com/en/docs/claude-code).
- **Auth:** Glade runs on your own Claude Code login (or `ANTHROPIC_API_KEY`, if you have one set). It never asks for or stores your credentials.
- **Install:** download `Glade-0.31.1-arm64.dmg` below, open it and drag Glade to Applications. Your workspaces and tasks from 0.31.0 carry over.
- **First launch:** Glade isn't notarised by Apple yet, so the first time, right-click Glade in Applications and choose Open (on newer macOS, if there's no Open button, click Open Anyway in System Settings › Privacy & Security). If macOS still won't open it, run `xattr -dr com.apple.quarantine /Applications/Glade.app` and try again.
- **Logs:** `~/Library/Logs/glade/main.log`, one JSON line per event, rotated at 5 MB. They stay on your Mac; attach them to a bug report if you like (`docs/logs.md` says what's in them).
