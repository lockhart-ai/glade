Glade 0.23.0 adds Broadcast, tells plugins when a task still has watchers running, and carries more of the agent
sandbox, which now has a switch in Settings but is not finished.

- **Broadcast (#507, issue #489).** ⌘⇧B (rebindable; File › Broadcast…) opens a modal: type one message and it goes
  to every Active task in every workspace. The modal lists who gets it, grouped by workspace, with each task's
  state, and says how many. An idle agent starts a turn with it; a busy one (mid-turn, paused, or waiting on a
  question or a permission card) gets it at the end of its queue, when its turn ends. Done tasks get nothing, and
  neither does a task that has never been sent anything. In each chat the message is yours with a small `BROADCAST`
  tag; each agent answers in its own chat. ↵ sends, ⇧↵ is a new line, Esc cancels and drops what was typed.
- **Answered permission cards leave the chat (#504).** A permission card shows in the chat only while it waits for
  you; once answered or withdrawn, the decision shows on the call's row in the Tool calls list (and a subagent's on
  its row in the Subagents tab). This is on for everyone.
- **Plugins are told how many watchers a task has running (#502, issue #490).** `PluginTask.watchers`: monitors and
  background commands still running under the task, its subagents' included; only the count. With the subagent
  events it lets a plugin tell a task that is idle from one whose turn is over and still waits on something.
  Nekomata will use it so a cat sleeps only when nothing is alive under it; that needs an update of the Nekomata
  plugin too.

## Under the hood

- **The agent sandbox has a switch now, and is not finished (#453, #505, #510, #513).** Settings › Agent has a
  Sandbox group with the **Run agents in a sandbox** switch and Glade-wide folder and domain grants, and Settings ›
  Workspace has the workspace's own. It is off by default. The sandbox's permission cards also landed this release —
  a folder, a domain, or running a command outside the sandbox, each answered from the chat — so a sandboxed agent
  can ask for access as it works; what's left before the switch defaults to on is the phase's security review and
  its fixes, and treating an MCP server, `SendMessage` and `RemoteTrigger` as grants of their own (both tracked on
  the sandbox's meta issue, #452). Leave the switch off until those land, unless you want to try it.
- **The e2e specs run their main-process calls on a turn of their own (#509, issue #486).** A rare CI failure ("This
  database connection is busy executing a query") came from Playwright's `app.evaluate` running a spec's function
  inside one of main's own queries. Only the test harness could do that; no app behaviour changed. A lint rule keeps
  specs on the new helper.

## Running it

- **Requirements:** a Mac with Apple silicon, logged in to [Claude Code](https://docs.claude.com/en/docs/claude-code).
- **Auth:** Glade runs on your own Claude Code login (or `ANTHROPIC_API_KEY`, if you have one set). It never asks for or
  stores your credentials.
- **Install:** download `Glade-0.23.0-arm64.dmg` below, open it and drag Glade to Applications. Your workspaces and
  tasks from 0.22.0 carry over.
- **First launch:** Glade isn't notarised by Apple yet, so the first time, right-click Glade in Applications and choose
  Open (on newer macOS, if there's no Open button, click Open Anyway in System Settings → Privacy & Security). If macOS
  still won't open it, run `xattr -dr com.apple.quarantine /Applications/Glade.app` and try again.
- **Logs:** `~/Library/Logs/glade/main.log`, one JSON line per event, rotated at 5 MB. They stay on your Mac;
  attach them to a bug report if you like (`docs/logs.md` says what's in them).
