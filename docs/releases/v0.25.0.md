0.25.0 turns on the todo hub: the right panel is now Agents · Files · Todos, and a task's todos hold the work it
produced. Question and permission cards are purple like every reply.

- **The todo hub is on (P16: #550 turned it on; built by #527, #539, #540, #543, #544, #545, #546, #541, #549).** The
  right panel's seven tabs are now three: **Agents**, **Files** and **Todos**. Agents is what's happening: Main's own
  tool calls, then a tab per subagent with its tool calls, and the Tool calls, Subagents and Watchers tabs are gone
  (#544, #546). Todos is what a task produced: a file, a link or a commit shows as a tile under the todo it was made
  for, filed as it's made rather than left for you to sort — a file's tile opens it in Files or the image viewer, a
  link's tile opens your browser, and a commit's tile opens to its branch, its subagent and its files (#543, #540,
  #539); the Artifacts and Changes tabs are gone with it (#545, #550). A todo's own text now links a `PR #511`,
  `#511` or a Jira key like `API-123` straight to the task's matching link artifact (#527). A running watcher pins
  under the tool calls of the agent that started it, with Stop, and becomes a row in that agent's history once it
  ends (#546). The hub's old hidden switch is gone outright, not just defaulted on: the setting itself is deleted
  (migration 0064), so there is no way to turn it off.
- **Question and permission cards are purple (#542, issue #538).** Both cards, the sandbox's included, sit on the
  same purple as every agent reply, with purple-tinted tiles, pills and fields inside them and nothing black. Inline
  code chips stay black, as agreed on the issue.

## Under the hood

- **The sandbox's zero-grant escape battery (#524):** an e2e run that points the real agent backend at a local
  stand-in for the model, then puts a sandboxed task with nothing granted and every card denied through about 320
  attacks in a throwaway home folder and workspace. It passes only if no attack reached the model, nothing was
  written outside the workspace, no listener was reached and the grants stayed empty.
- The sandbox switch still defaults to off (`sandboxEnabled: false` in `src/shared/settings.ts`). What's left before
  it flips: issue #452, the phase's final docs pass, is still open.
- Migrations added since v0.24.0:
  - **0062**, for filing produced work under a todo as it's made (`owed_filings`, `session_context.todo_hub`).
  - **0063**, for remembering which agent's tab each task is on (`agents.setTab`).
  - **0064**, for collapsing the todo hub's hidden switch away now that the hub is on for everyone.

## Running it

- **Requirements:** a Mac with Apple silicon, logged in to [Claude Code](https://docs.claude.com/en/docs/claude-code).
- **Auth:** Glade runs on your own Claude Code login (or `ANTHROPIC_API_KEY`, if you have one set). It never asks for or
  stores your credentials.
- **Install:** download `Glade-0.25.0-arm64.dmg` below, open it and drag Glade to Applications. Your workspaces and
  tasks from 0.24.0 carry over.
- **First launch:** Glade isn't notarised by Apple yet, so the first time, right-click Glade in Applications and choose
  Open (on newer macOS, if there's no Open button, click Open Anyway in System Settings → Privacy & Security). If macOS
  still won't open it, run `xattr -dr com.apple.quarantine /Applications/Glade.app` and try again.
- **Logs:** `~/Library/Logs/glade/main.log`, one JSON line per event, rotated at 5 MB. They stay on your Mac;
  attach them to a bug report if you like (`docs/logs.md` says what's in them).
