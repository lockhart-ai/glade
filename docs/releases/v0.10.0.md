Glade 0.10.0 adds per-call permission review: a task can ask before it edits files or runs commands.

## New

- **Ask before edits and commands.** The input bar's Permissions picker now has a second mode next to Allow all. In it,
  file edits and writes, commands and other tools with side effects wait on a **permission card** in the chat, showing
  the command or the change. Reads, searches and Glade's own tools never ask. Settings › Agent › Permissions sets the
  default for new tasks; Allow all stays the default.
- **Allow once, Allow for this task, or Deny.** Allow for this task remembers that command prefix (say, `npm test`
  commands) or that tool for the rest of the task, across relaunches, and only in that task. Deny can carry a note that
  the agent reads. The keyboard works too: ← → between the buttons, ↵ to choose.
- **It needs you.** While a card waits, the task shows the purple dot and counts in Needs you, and you get a
  notification if you're looking elsewhere, just as with a question.
- **Survives a relaunch.** A card open when Glade quits is still there when it comes back; answering it tells the agent
  and carries the task on, and the call it re-issues doesn't ask again.

## Running it

- **Requirements:** a Mac with Apple silicon, logged in to [Claude Code](https://docs.claude.com/en/docs/claude-code).
- **Auth:** Glade runs on your own Claude Code login (or `ANTHROPIC_API_KEY`, if you have one set). It never asks for or
  stores your credentials.
- **Install:** download `Glade-0.10.0-arm64.dmg` below, open it and drag Glade to Applications. Your workspaces and
  tasks from 0.9.0 carry over.
- **First launch:** Glade isn't notarised by Apple yet, so the first time, right-click Glade in Applications and choose
  Open (on newer macOS, if there's no Open button, click Open Anyway in System Settings → Privacy & Security). If macOS
  still won't open it, run `xattr -dr com.apple.quarantine /Applications/Glade.app` and try again.
- **Logs:** `~/Library/Logs/Glade/main.log`, one JSON line per event, rotated at 5 MB. They stay on your Mac;
  attach them to a bug report if you like (`docs/logs.md` says what's in them).

## Calls made without Jared (please review)

- `WebFetch` and `WebSearch` count as reads and never ask. (planning)
- Other MCP servers' tools, and any tool Glade doesn't know, ask. A user `permissions.ask` rule shows the card even for a read. (planning)
- Settings › Agent's existing "Ask first" option becomes this mode; "Allow edits" stays disabled. (planning)
- The probe showed a live session can switch between Allow all and ask mode, both ways, with no restart. (#177)
- When you deny a call, the agent is told "The user denied permission for this tool call, so it did not run.", plus " They said: <note>" if you added one. (#177)
- These also run without asking: LS, NotebookRead, TaskGet, TaskList, TaskOutput, TaskStop. BashOutput, KillShell and ExitPlanMode ask. (#177)
- A background subagent's permission requests belong to the subagent: Stop doesn't withdraw them; only the session closing does. (#177)
- Requests still open when the app quits stay open, like questions do. Picking up the task from them is P11-04. (#177)
- In ask mode, ScheduleWakeup and the Cron tools never ask (they only schedule the agent itself). Monitor asks, because it runs a shell command. (#177/#178)
- Allow once and Deny share one tab stop, with ← → between them, so ↵ approves (Deny takes that spot when the SDK says a stray key mustn't approve). A card takes focus only when focus is on nothing or already in the chat. (#178)
- Deny opens a note field: ↵ sends, Esc keeps the draft, and a blank note denies without one. (#178)
- The card trims its input at 12 lines or 1,200 characters, with Show all. Tools other than Bash, Edit, MultiEdit and Write show their input as JSON. (#178)
- SendMessage and RemoteTrigger ask. PushNotification and ListAgents never ask. (#178)
- Settings keeps the label "Ask first" for the new mode. (#178)
- "Allow for this task" isn't offered when the SDK suggests more than one rule (compound commands). Bash is never allowed as a whole tool. (#179)
- A second card for the same tool stays open when a rule is granted; it was asked before the rule existed, and you answer it on its own. (#179)
- Tools with no suggested rule (Write, MCP tools) are allowed as a whole tool. Rules live in SQLite per task and reach the SDK as `allowedTools`; nothing is written to your Claude settings files. (#179)
- There's no UI to see or remove a task's rules (as decided in P11 planning). (#179)
- After a relaunch, the agent hears about the decisions on requests left open by the quit in one batch, once they're all decided. (#180)
- When the agent re-issues the same call (same tool, same input exactly), it's let through once without a second card, within the resumed turn. (#180)
- While such a card is open, messages you send are queued. A paused task waits on you instead of retrying, and an errored task keeps its error until you answer. (#180)

## Open questions

- **Seeing a task's granted rules.** There's no way to see or remove what Allow for this task granted; the designs don't
  show one. Should there be?

## Please check by hand

- **Switch a task to Ask before edits and commands** and have the agent edit a file and run a command: each waits on a
  card; Allow once, Allow for this task (the next matching command doesn't ask) and Deny with a note (the agent reacts
  to it).
- **Quit Glade with a card open**, reopen it, and answer the card: the agent carries on.
- **Settings › Agent › Permissions:** Ask first makes new tasks start in the ask mode.
