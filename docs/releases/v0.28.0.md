0.28.0 makes agents and tasks show their activity more truthfully: a subagent that left a watcher running stays
counted as waiting, and every task can now see the other Active tasks and their PR links before it picks work up.
OpenRouter got its Settings polish — sorted, searchable provider menus — plus an optional management key, and
context and token figures that finally read true.

## Agents and tasks

- **Every task can see the other tasks.** A new read-only `list_other_tasks` call returns the Active tasks across
  every workspace, most recently updated first, each with its title, goal, status, attention, workspace and PR
  links; the system prompt tells an agent to check it before starting work on an existing PR, issue or branch, and
  to stop and ask if another task already has it (#583).
- **A subagent waiting on a watcher stays counted.** A subagent whose own turn ended but that left a watcher,
  wakeup or background command running no longer drops out of the task row's subagent count — it shows as waiting
  ("3 subagents: 2 running, 1 waiting on a watcher") — and the Agents tab's dots use the same rule, so nothing
  reads done while something under it is still alive (#586).
- **The Todos bar fills an in-progress item's whole share.** An in-progress item's share is now all blue instead
  of half grey, so a bar where every item is done or in progress no longer has a grey stretch that reads as
  not-started work (#585).

## OpenRouter

- **Settings polish, a management key, and Main's line on the Agents tab.** Both provider lists are alphabetised
  and scrollable, selected models sit in a `Selected · N` section above the catalog, and search matches every
  word against the id, name or description, folding diacritics. An optional management key (encrypted like the
  inference key) is validated as it connects by reading the account's guardrails, and both provider lists filter
  to the allowed providers. Main gets the same two-row model-and-status line the subagents already had (#570).
- **Main's token totals on its Agents tab line.** Main's line shows `1.2M in · 45k out`, taken from each finished
  turn's final `result.usage` (input and cache tokens together), whether the turn succeeded, failed or was
  stopped (#588).
- **The context tracker counts OpenRouter usage.** OpenRouter's streamed frames carry zeros until the turn ends,
  so a task's context figure used to read 0 forever and a switch from Claude mid-conversation erased the
  carried-over figure; zero reports are now ignored and the turn's real figure comes from its result (#569).
- **The context figure is no longer a sum of the turn's requests.** A turn's `result.usage` sums every main-loop
  request in the turn, so the meter over-read by roughly the number of tool round-trips; the runner now takes the
  last request's own figure, or the SDK's own estimate once at the end of the turn, never a sum (#581).

## Running it

- **Requirements:** a Mac with Apple silicon, logged in to [Claude Code](https://docs.claude.com/en/docs/claude-code).
- **Auth:** Glade runs on your own Claude Code login (or `ANTHROPIC_API_KEY`, if you have one set). It never asks for or
  stores your credentials.
- **Install:** download `Glade-0.28.0-arm64.dmg` below, open it and drag Glade to Applications. Your workspaces and
  tasks from 0.27.0 carry over.
- **First launch:** Glade isn't notarised by Apple yet, so the first time, right-click Glade in Applications and choose
  Open (on newer macOS, if there's no Open button, click Open Anyway in System Settings → Privacy & Security). If macOS
  still won't open it, run `xattr -dr com.apple.quarantine /Applications/Glade.app` and try again.
- **Logs:** `~/Library/Logs/glade/main.log`, one JSON line per event, rotated at 5 MB. They stay on your Mac;
  attach them to a bug report if you like (`docs/logs.md` says what's in them).
