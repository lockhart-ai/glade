v0.40.0 tells a task when one of its linked pull requests gets merge conflicts, and wakes its agent to deal with them.

## What a user notices

- **Merge conflicts on a linked PR are noticed (#771, PR #772).** When another change lands first and a task's open PR can no longer merge, the task gets a GitHub update, "has merge conflicts", and its agent wakes, like any other GitHub notice. When the conflicts are fixed, it gets "merge conflicts resolved". PRs that are already conflicting when you update are reported on their next check.

## Under the hood

- The GitHub watcher reads each linked PR's `mergeable` answer, through GraphQL and through the REST fallback. GitHub works it out lazily, so an "unknown" answer is never reported and the last known one stands, which keeps the notice from flickering. A merged or closed PR is never reported as conflicting (#772).
- Migration 0085 adds the column that remembers the last known answer (#772).

## Running it

- **Install:** download `Glade-0.40.0-arm64.dmg` below, open it and drag Glade to Applications. Your workspaces and tasks carry over.
- **Database:** one migration, 0085 (`github_link_watches.mergeable`); it runs on first launch and only goes forward.
- **Signing:** the same self-signed certificate as before, so macOS permission grants carry over.
