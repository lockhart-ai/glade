Glade 0.20.1 is a small patch release fixing two bugs: quitting could show "A JavaScript error occurred in the main
process" instead of quitting, and pressing Stop with messages queued left them stuck.

- **Quit no longer shows a JavaScript error.** Quit closes every window before the menu bar shuts down. A menu bar
  refresh pending on its 100 ms timer could still be sent to the popover's closed window and throw, which anyone who
  had opened the menu bar popover once and quit within about 100 ms of a task or workspace change could hit. Glade now
  drops the popover when its window closes. Test and capture runs exit on an uncaught main-process error instead of
  showing the dialog, and an e2e test fails if its app logged one. (#440)
- **Stop no longer strands a queued message.** Pressing Stop with messages queued left them stuck. Stop now stops the
  turn and sends the queue as the next turn, in order; a task already stuck in that state sends its queue at launch.
  (#443)

## Running it

- **Requirements:** a Mac with Apple silicon, logged in to [Claude Code](https://docs.claude.com/en/docs/claude-code).
- **Auth:** Glade runs on your own Claude Code login (or `ANTHROPIC_API_KEY`, if you have one set). It never asks for or
  stores your credentials.
- **Install:** download `Glade-0.20.1-arm64.dmg` below, open it and drag Glade to Applications. Your workspaces and
  tasks from 0.20.0 carry over.
- **First launch:** Glade isn't notarised by Apple yet, so the first time, right-click Glade in Applications and choose
  Open (on newer macOS, if there's no Open button, click Open Anyway in System Settings → Privacy & Security). If macOS
  still won't open it, run `xattr -dr com.apple.quarantine /Applications/Glade.app` and try again.
- **Logs:** `~/Library/Logs/glade/main.log`, one JSON line per event, rotated at 5 MB. They stay on your Mac;
  attach them to a bug report if you like (`docs/logs.md` says what's in them).

## Calls made without Jared (please review)

- A stuck task (active, waiting, messages queued, no turn running, no open question or permission card) sends its
  queue at launch; pressing Stop with no turn running on such a task also sends it; a stopped manual compaction with
  messages queued sends them too. A task marked done mid-turn keeps its queue rather than sending it. A second press
  of Stop stops the turn the queue just started — no guard was added against that. Stop still ends only the turn, so
  background subagents keep running. (#443)
- A real run still shows Electron's own error dialog on an uncaught main-process error; only test and capture runs
  exit instead. (#440)
