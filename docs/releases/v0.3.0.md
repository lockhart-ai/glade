Glade 0.3.0 is about long tasks that keep going: through a full context, a flaky API, a usage limit or a crash.

## What's new

- **Context meter and compaction.** Click the context meter under the input to see how full the task's context is and
  where it compacts on its own. Compact now (or ⌘⇧K from anywhere in the task) compacts it straight away: the agent
  works while it does, the chat marks where, and the meter drops.
- **Automatic compaction.** When a long turn fills the context, the agent compacts on its own and carries on. The
  chat shows a divider, the tool log gets a Compact row, and nothing is lost: the full chat and tool log stay in Glade.
- **Errors you can recover from.** Claude Code retries an overloaded or failing API with backoff, and Glade shows
  "Retrying (2 of 3)" while it does. If it still fails, the task stops with a card saying what happened, with Retry,
  Retry with another model and Show details. The chat, tool log and files are as they were.
- **Usage limits and going offline.** Hitting your usage limit, or losing the network, pauses the affected tasks
  instead of failing them, behind one banner across the top of the app. They resume on their own when the limit
  resets or the network comes back. Switch model resumes them now on another model, and Details lists the paused
  tasks and what the API said. Messages you send meanwhile wait in the queue.
- **Crash recovery.** If Glade quits unexpectedly with tasks mid-turn, they all pick up where they left off when you
  open it again, and queued messages are still delivered. A notice says how many resumed (Show them opens one), and
  the chat and tool log mark the restart. A clean quit shows no notice.

## Running it

- **Requirements:** a Mac with Apple silicon, logged in to [Claude Code](https://docs.claude.com/en/docs/claude-code).
- **Auth:** Glade runs on your own Claude Code login (or `ANTHROPIC_API_KEY`, if you have one set). It never asks for or
  stores your credentials.
- **Install:** download `Glade-0.3.0-arm64.dmg` below, open it and drag Glade to Applications. Your tasks from 0.2.0
  carry over.
- **First launch:** Glade isn't notarised by Apple yet, so the first time, right-click Glade in Applications and choose
  Open (on newer macOS, if there's no Open button, click Open Anyway in System Settings → Privacy & Security). If macOS
  still won't open it, run `xattr -dr com.apple.quarantine /Applications/Glade.app` and try again.

Not in this release: the terminal and plugin panels, search, the other right-panel tabs and Settings. Those come in
later phases.

## Calls made without Jared (please review)

- **Tested with a scripted agent only.** Every build has been exercised against Glade's scripted fake agent in the
  tests, not a real one. Real usage-limit reset times come from the SDK's `rate_limit_event`, and haven't been seen
  live yet.
- **Compact now** is disabled while the agent is working, rather than queued. A compaction runs like a turn: the task
  shows as working, queued messages wait, and Stop works.
- **The auto-compact threshold** shown is the window minus 20k minus 13k (167k on a 200k window, 97% on 1M). The ring
  turns purple within 10% of the window below it.
- **No custom threshold.** The design's "Change the threshold in Settings" line is left out until Settings exist.
- **Compaction in the tool log** is a new kind of row. Migration 8 rebuilds the tool log table to allow it.
- **Automatic compaction** shows a running Compact row as soon as the SDK reports it's compacting. If a compaction
  fails, its row ends as an error and the turn carries on.
- **Glade doesn't retry on top of Claude Code,** which already retries overloaded, 5xx, 429 and network errors with
  backoff. Glade shows its progress, then the card with the retry history.
- **Retry** re-sends your last message in the same session, so the model sees it twice. No new chat message is added.
- **Retry with another model** opens a model menu on the card.
- **The failed request** shows in the tool log as an "API" call.
- **Compacting an errored task** leaves the old error saved but hidden, since the card only shows while the task is
  stopped by an error.
- **Usage limits and offline pause** instead of erroring, as a new "paused" state. A usage limit resumes at the reset
  time the SDK reports (subscription accounts), or after 15 minutes if it gives none. Offline checks for the network
  after 5 seconds, then waits twice as long each time, up to a minute.
- **Paused tasks** get a blue dot, don't count as Needs you, and can be marked done. Compact is refused while paused.
- **The pause banner** counts tasks across all workspaces. With different reset times it shows the latest. Every
  paused row in the sidebar reads "Paused: usage limit · resumes HH:MM", where the design mixes in the agent's status
  on one row.
- **The relaunch notice** shows only after a crash that cut tasks off mid-turn which then resumed, never after a clean
  quit. Show them opens the first resumed task (switching workspace if needed) and dismisses the notice.
- **A compaction cut off by a crash** isn't redone; its row ends "Didn't finish".
- **A crash before the session started** re-sends the turn's messages to a new session.
- **Verification notes:** `16-error`, `17-usage-limit`, `18-relaunch` and `19-compaction` match apart from sample data
  and small spacing (the workspace header sits a little lower, as in 0.2.0). Differences worth a look: a tool call cut
  off by a crash ends as a red "Glade quit before this tool call finished." where `18-relaunch` shows a grey
  "Interrupted at 1,240"; the retried request row reads "request 4 of 4" (3 retries after the first), where
  `16-error` says "3 of 3"; and narration in the tool log shows `code` with literal backticks, where the designs
  render it as code.
