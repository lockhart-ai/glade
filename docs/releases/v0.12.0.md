Glade 0.12.0 lets agents and scripts drive Glade: create, update and finish tasks, import your Claude Code history,
and backfill past tasks from your notes. It also brings a more compact task header, a little more contrast, and task
switching from the keyboard while you type.

## New

- **Let agents control Glade** (Settings › Control, off by default). Turned on, Glade serves its `glade-control` tools
  on this Mac only, behind a token:
  - **In Glade's own tasks,** so you can ask a task to port your old sessions in or tidy other tasks.
  - **To any other chat:** Settings shows a ready-to-paste `claude mcp add …` command.
  - **To scripts:** a plain JSON endpoint (`POST /v1/tools/<name>`) next to the MCP one, and Glade's agents get
    `GLADE_CONTROL_URL` and `GLADE_CONTROL_TOKEN` in their environment, so a script they write just works.

  The tools list, read, create, update, message, stop, finish, reopen and delete tasks (deleting needs
  `confirm: true`). In the ask permission mode, changes wait on a card; reads never ask. See `docs/control-api.md`.
- **Import Claude Code sessions.** `list_claude_code_sessions` and `import_claude_code_session` turn a Claude Code
  transcript into a Glade task: its chat, tool calls and times, in the workspace for its folder. Send a message and
  it resumes that very session. Importing the same session twice gives the same task.
- **Backfill past tasks with a handoff note.** `create_task` can take a Markdown handoff note (what the task was, where
  it got to, what's next, where its notes live), artifacts, its original start date and an `externalId`, so a
  backfill can be rerun safely. The note shows as a **Backfilled** card at the top of the chat, and the agent always
  has it: send "let's pick this up" and it knows where it was.
- **A compact task header:** a state dot, the title and its age on one line, pin and Mark done as icons, and GOAL /
  NOW underneath.
- **⌥↑ / ⌥↓ switch tasks from the input bar,** and each task keeps its draft (text and pasted images), even across a
  relaunch.
- **A little more contrast** between cards, panels and borders, for bright rooms; faint text is 4.5:1 everywhere.

## Running it

- **Requirements:** a Mac with Apple silicon, logged in to [Claude Code](https://docs.claude.com/en/docs/claude-code).
- **Auth:** Glade runs on your own Claude Code login (or `ANTHROPIC_API_KEY`, if you have one set). It never asks for or
  stores your credentials.
- **Install:** download `Glade-0.12.0-arm64.dmg` below, open it and drag Glade to Applications. Your workspaces and
  tasks from 0.11.0 carry over.
- **First launch:** Glade isn't notarised by Apple yet, so the first time, right-click Glade in Applications and choose
  Open (on newer macOS, if there's no Open button, click Open Anyway in System Settings → Privacy & Security). If macOS
  still won't open it, run `xattr -dr com.apple.quarantine /Applications/Glade.app` and try again.
- **Logs:** `~/Library/Logs/Glade/main.log`, one JSON line per event, rotated at 5 MB. They stay on your Mac;
  attach them to a bug report if you like (`docs/logs.md` says what's in them).

## Backfilling, step by step

1. Settings › Control: turn on **Let agents control Glade**.
2. Open a task in the workspace your notes belong to and ask, for example: *"Write a script that goes through each
   folder in ~/work/tasks, reads its notes, and creates a Glade task for it through `$GLADE_CONTROL_URL/v1/tools/create_task`
   with a title, objective, status, a handoff note, its files as artifacts, its original start date, `state: done`,
   and the folder path as `externalId`. Then run it."*
3. To port Claude Code history instead: *"List my Claude Code sessions with list_claude_code_sessions and import
   each one."*

## Calls made without Jared (please review)

- Settings gets a new Control section, after Plugins. (planning)
- create_task has no start flag: giving a first message starts the task; leaving it out makes a task that waits for one. (planning)
- Through the API, a task can't stop itself, delete itself or send itself a message. It can read and update itself. (planning)
- Reading through the API doesn't mark a task read, and messages sent through it show as yours. (planning)
- Imports go only into the workspace whose root is exactly the transcript's folder. With no such workspace the import fails unless createWorkspace is true. (planning)
- Imported tasks are Done by default, with status "Imported from Claude Code". Thinking, subagent transcripts, slash commands and images are left out. (planning)
- Port 45233 by default, falling back to the next nine. The token is stored in SQLite, and regenerating it asks for no confirmation. (planning)
- The copy-ready command names the server `glade-control`, so it can't clash with Glade's own in-process `glade` server. (planning)
- Paging through list_tasks keeps the listing's order for 10 minutes. An expired cursor means listing again. (#220)
- In the ask mode, glade-control's reads never ask, and its changes (create, update, send, done, delete) wait on a permission card like any other tool call. (#220)
- get_chat lists only the agent's own tool calls, not its subagents'. create_task doesn't switch the window to the new task. (#220)
- Scripts get a plain JSON endpoint beside /mcp. Agent sessions get GLADE_CONTROL_URL and GLADE_CONTROL_TOKEN when control is on. The change limit is about 1,200 a minute. (#222)
- Imported titles come from a /rename title first, then Claude Code's own title, then its summary. Image-only prompts show as "[Image]", and interruption markers are skipped. (#221)
- Transcript model ids lose their date (claude-haiku-4-5-20251001 → claude-haiku-4-5). (#221)
- a resumed Claude Code session keeps the system prompt it started with, so Glade's appended instructions don't apply to imported sessions. #225 delivers Glade's context in the first message instead. (#221)
- Regenerating the token stops the old one on the very next request; nothing restarts. Running agent sessions keep the old env values until their next session. (#222)
- Rate limits are 1,200 changes and 3,000 reads a minute per caller. (#222)
- A `glade-control` MCP server in your own Claude Code config is always blocked in Glade's sessions, so its tools don't show up twice. (#222)
- The Copy button gives no "Copied" feedback, and the Port field saves on Return or blur. (#222)
- Surfaces, borders, muted and faint went up 1.4–4.5 points of lightness; hue, the window background and accent tints are unchanged. Faint text now meets 4.5:1 everywhere, and a test holds the minimums. (#226)
- ⌥↑/⌥↓ switch tasks from the message field and anywhere outside text fields. Search, rename, Settings fields, the question text answer, the Deny note, the queued-message editor and the terminal keep their native ⌥↑/⌥↓. Input drafts, pasted images included, now survive switching tasks. (#230)
- A backfilled task's artifacts must be files inside its workspace (the Files and Artifacts tabs only read there). Notes kept elsewhere can be named in the handoff note, and the agent can read them, but they aren't clickable artifacts. (#225)
- A handoff note reaches a new session through the system prompt, and an existing (resumed) session once, as a block in front of your next message. Imported Claude Code sessions get Glade's instructions the same way on their first message. (#225)
- A done backfill can't also carry a first message. A future startedAt is refused. The Backfilled card starts open; long notes scroll inside it. (#225)
- Also fixed: sending a message to a done task that never had a turn failed with an internal error. (#225)
- The header's state dot is the same component as the sidebar's, so the two always agree; its label (e.g. "Active · waiting on you") is the tooltip. Ages read now / 4m / 1h 49m / 3d; a done task shows its run times instead. (#231)
- The pin stays the solid thumbtack (Font Awesome's free set has no outline one). Paddings stay on the spacing scale, so the header is about 2px off your mockup in places. (#231)
- Input drafts, pasted images included, are saved in SQLite 400ms after you stop typing, and at once on switching tasks or quitting. Anything typed in the last 400ms before a crash is lost. Saves that fail are silent. (#235)
