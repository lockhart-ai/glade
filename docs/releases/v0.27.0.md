0.27.0 is four follow-ups to the OpenRouter landing in v0.26.0, all about a dispatched child (the `dispatch` tool, for
a child on the *other* source from its parent): the effort it starts at, the git worktree it can work in, and the
prompt and tools it gets.

- **A dispatched child starts at its parent's effort**, not always Low. It takes the parent's effort at the moment
  of the dispatch, clamped to the nearest effort its own model offers when the exact one isn't available. A resumed
  child keeps following the same rule.
- **`dispatch` takes `isolation: "worktree"`**, the same name and value as the built-in `Agent` tool's. With it, the
  child's session starts in its own git worktree (`.claude/worktrees/<child id>` on branch `worktree-<child id>`),
  made by Claude Code's own `--worktree` flag so Glade's own git stays read-only (#487). A resumed child goes back
  into the worktree its first run had, and a child's own children share it unless they ask for their own. A
  sandboxed session refuses it, since it isn't offered `EnterWorktree` either (#514).
- **A dispatched child gets its own short prompt and only the tools it may use**, instead of a copy of the main
  agent's whole Glade prompt and every Glade tool (most of them refused anyway by the main-only guard, #366). It's
  told only what a subagent needs: it's doing the parent's task, its final message is what the parent reads, and it
  finishes its own descendants before returning. An unsandboxed child gets no `glade` or `glade-control` tools at
  all; a sandboxed one gets `request_access` only (#450). Every child keeps `glade-agents`, so it can still dispatch
  its own children.
- **Nothing changes for a task that never dispatches a child**, and native `Agent` subagents (same-source children)
  are unaffected throughout.

## Under the hood

- Migrations added since v0.26.0:
  - **0067**, for a dispatched child's worktree: an added `worktree` column on `managed_agents`, so a resumed child
    goes back into the one it started in.
- The sandbox switch still defaults to off (`sandboxEnabled: false` in `src/shared/settings.ts`).

## Running it

- **Requirements:** a Mac with Apple silicon, logged in to [Claude Code](https://docs.claude.com/en/docs/claude-code).
- **Auth:** Glade runs on your own Claude Code login (or `ANTHROPIC_API_KEY`, if you have one set). It never asks for or
  stores your credentials.
- **Install:** download `Glade-0.27.0-arm64.dmg` below, open it and drag Glade to Applications. Your workspaces and
  tasks from 0.26.0 carry over.
- **First launch:** Glade isn't notarised by Apple yet, so the first time, right-click Glade in Applications and choose
  Open (on newer macOS, if there's no Open button, click Open Anyway in System Settings → Privacy & Security). If macOS
  still won't open it, run `xattr -dr com.apple.quarantine /Applications/Glade.app` and try again.
- **Logs:** `~/Library/Logs/glade/main.log`, one JSON line per event, rotated at 5 MB. They stay on your Mac;
  attach them to a bug report if you like (`docs/logs.md` says what's in them).

## Calls made without Jared (please review)

- A dispatched child's worktree is kept when the child ends, even unchanged, and it's left to the parent to remove:
  Glade's own git only reads (#487), so Glade itself never runs `git worktree remove` (#558).
- A dispatched child's worktree starts from the remote's default branch, the same as a native `Agent` child's
  worktree isolation, rather than the branch the parent happens to be on (#558).
- A sandboxed session refuses `isolation: "worktree"` outright rather than working out the sandbox's bounds inside
  a worktree (#558).
- An unsandboxed dispatched child gets none of Glade's own tools; a sandboxed one gets `request_access` only, so it
  can still ask for a folder the sandbox blocked (#560).
- All four PRs were written by GLM 5.3 Flash children dispatched through OpenRouter, from the supervisor's briefs;
  the supervisor reviewed each diff (#557, #559, #561, #563).

**For Jared to check, not yet run with a real model:** a dispatch with `isolation: "worktree"` — a model actually
working in the worktree, and a child with its own child sharing one worktree at once; and a dispatched child working
from its new short prompt. Both were tested so far only with the scripted test backend and no-model SDK probes.

**Known limitations / open:** the note a limit-switch gives the new session is kept in memory only, so quitting or
crashing Glade after the switch and before the next prompt loses it (#564, filed, not started). The remaining
OpenRouter follow-ups — child effort choice, cross-route children, cost attribution, usage-accounting gaps, and the
rest — are listed in `docs/openrouter-integration-spec.md`, "Landing limitations and follow-ups". The cleared-limit
path still assumes a window's reset time is the same in every reading (#533); session starts still aren't staggered,
so a broadcast or a relaunch can spawn many Claude Code processes at once (#512); a subagent evicted by a
safety-refusal fallback still stays "running" for plugins until their next snapshot (#503).
