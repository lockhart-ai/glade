0.24.0 is about usage limits: paused tasks can be resumed with a click, resume by themselves when the account can run
again, and the usage meter shows extra usage as soon as it's on. It also carries more of the sandbox (still off by
default) and the first parts of the todo hub, which is built switched off.

- **Resume now (#521, issue #519).** The usage-limit banner has a Resume now button beside Switch model: one click
  retries every task paused on a usage limit, in every workspace, on its own model. A task still over the limit
  pauses again with the reset time it's given.
- **Paused tasks resume by themselves when the account can run again.** While anything is paused on a usage limit,
  Glade reads usage again when its window gets the focus and every 5 minutes, and resumes the paused tasks when the
  limit that stopped them has cleared or extra usage is on with room left. A task is retried again only when that
  availability changes, so a wrong reading can't loop.
- **The usage meter shows Extra usage as soon as it's on.** Until now the row was missing while nothing had been
  spent (Claude Code gives no percentage then).

## Under the hood

- **Sandbox (still off by default):** the phase's security review and its fixes (#518) close what the review found —
  path spellings Glade couldn't resolve, a granted folder swapped for a symlink, the user's own Claude Code settings
  letting a call skip Glade's checks, files that run code reachable inside a grant, and the sandbox-control token
  reaching a command's environment. Two of its fixes apply to everyone, sandbox on or off: **Open in editor** now
  always hands the file to the default text editor as text (`open -t`), never running it, and an attached image never
  follows a symlink swapped in since it was copied, even one pointing outside the workspace. Everything else it fixes
  — the wider fixed credential denies, the run-outside-the-sandbox card, the resolved-path and magic-folder checks,
  write-protecting files that run code under a grant — only takes effect once the switch is on. MCP servers,
  SendMessage and RemoteTrigger as grants (#525) treat an MCP server Glade doesn't build (the user's Claude Code
  config, a repo's `.mcp.json`, a claude.ai connector), and a sandboxed agent's SendMessage or RemoteTrigger reaching
  another agent, as a grant of their own — one card and one Settings list per server, rather than a card per tool
  call. The switch (`sandboxEnabled` in `src/shared/settings.ts`) still defaults to off. What's left before it flips
  (P15's meta issue #445, and #452): the zero-grant escape battery (#516), the phase's acceptance test that runs the
  review's attacks on every PR, is still open, and then #452 itself — the final docs pass that turns the default on.
- **Todo hub, built switched off (#508, #506, #520, #522, #523):** the first parts of making the Todos tab the hub
  for what a task made. Its hidden setting (`todoHubEnabled`) is off with nothing in Settings, and with it off
  nothing of the hub is read, written, sent or shown — a dedicated test (`src/main/todo-hub/inert.test.ts`) holds
  that through the real wiring, and with the switch off the Todos tab looks and behaves exactly as it did before
  (#522's tools don't exist and the prompt says nothing of them; #523 leaves the tab unchanged, confirmed in its own
  screenshot). #508 probed how a child gets filed under a todo on Claude Code's own tools and wires nothing in; #506
  is the phase's screen designs, with no behaviour change. #520 adds the switch itself, a todo's id in the window,
  and the filing store; #522 adds the agent's `list_children` and `file_children` tools (main agent only); #523 shows
  the Todos tab as the hub once the switch is on. Migrations added since v0.23.0:
  - **0059**, for the todo hub's child ids, filings and panel state.
  - **0060**, for the MCP-server and other-agent sandbox grants, and the MCP servers a workspace's sessions have
    reported.

## Running it

- **Requirements:** a Mac with Apple silicon, logged in to [Claude Code](https://docs.claude.com/en/docs/claude-code).
- **Auth:** Glade runs on your own Claude Code login (or `ANTHROPIC_API_KEY`, if you have one set). It never asks for or
  stores your credentials.
- **Install:** download `Glade-0.24.0-arm64.dmg` below, open it and drag Glade to Applications. Your workspaces and
  tasks from 0.23.0 carry over.
- **First launch:** Glade isn't notarised by Apple yet, so the first time, right-click Glade in Applications and choose
  Open (on newer macOS, if there's no Open button, click Open Anyway in System Settings → Privacy & Security). If macOS
  still won't open it, run `xattr -dr com.apple.quarantine /Applications/Glade.app` and try again.
- **Logs:** `~/Library/Logs/glade/main.log`, one JSON line per event, rotated at 5 MB. They stay on your Mac;
  attach them to a bug report if you like (`docs/logs.md` says what's in them).
