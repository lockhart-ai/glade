v0.39.0 shows a local dev server live in the Files tab, so you can watch and play a game or web app while an agent changes it, and shows each subagent's prompt in the Agents tab.

## What a user notices

- **A local dev server, live in the Files tab (#764, PR #765).** An agent can open `http://localhost:<port>` with `show_file`'s new `url`, or you can with the globe button by the open-files row. The page runs live in its own tab, marked LIVE, and hot-reloads as the code changes. Click into it and arrow keys and Shift go to the page, not Glade. The path row has the URL, a reload button, whether it's connected, and Open in browser. It reaches only `localhost`, `127.0.0.1` and `[::1]`; anything else it asks for is blocked and named in a quiet line under the path row.
- **The Files tab's header collapses (#764, PR #765).** The ^ at the end of the path row hides the open-files row and the path row, so whatever is open fills the tab below Todos · Agents · Files. The chevron button in that top bar brings them back. It's kept per task and works for any file, not only a live page.
- **A subagent's prompt on its tab (#762, PR #763).** Pick a subagent in the Agents tab and a Prompt row under its "Working on" line shows the first line of what it was told; expand it to read the whole prompt, in a box that scrolls so the log stays in view.

## Under the hood

- A live page runs in its own sandboxed view and fresh session, never in Glade's own page: no Node, no preload, only `http` and `ws` to the literal loopback hosts, navigation away refused, downloads refused, fullscreen the only permission. Each refusal is logged. The offline HTML preview is unchanged (#764).
- The prompt is read from the subagent's starting call, which Glade already stored, so older subagents show theirs too (#762).

## Running it

- **Install:** download `Glade-0.39.0-arm64.dmg` below, open it and drag Glade to Applications. Your workspaces and tasks carry over.
- **Database:** no migrations in this release.
- **Signing:** the same self-signed certificate as before, so macOS permission grants carry over.
