Glade 0.8.1 fixes a bug that stopped the packaged app from starting any agent.

## Fixed

- **"Couldn't send your message: tasks.send failed: spawn ENOTDIR."** In 0.8.0 (and earlier packaged builds), the first
  message in any task failed. The app tried to start Claude Code from inside its own `app.asar` archive, which can't
  run programs. Glade now runs the unpacked copy that ships beside it (#158).
- **The release build now checks for this.** Each release packages the app and runs the bundled Claude Code before
  publishing, and a regression test rebuilds the packaged layout and spawns from it.

## Process

- Every bug-fix PR now includes a test that recreates the bug, and every feature PR includes tests that stress it
  (`docs/kitten-sop.md`).

## Running it

- **Requirements:** a Mac with Apple silicon, logged in to [Claude Code](https://docs.claude.com/en/docs/claude-code).
- **Auth:** Glade runs on your own Claude Code login (or `ANTHROPIC_API_KEY`, if you have one set). It never asks for or
  stores your credentials.
- **Install:** download `Glade-0.8.1-arm64.dmg` below, open it and drag Glade to Applications. Your workspaces and
  tasks from 0.8.0 carry over.
- **First launch:** Glade isn't notarised by Apple yet, so the first time, right-click Glade in Applications and choose
  Open (on newer macOS, if there's no Open button, click Open Anyway in System Settings → Privacy & Security). If macOS
  still won't open it, run `xattr -dr com.apple.quarantine /Applications/Glade.app` and try again.

## Please check by hand

- **A real agent turn in the installed app:** create a task and send a message. The release check and a one-turn probe
  both passed against the packaged build, but nobody has done a full turn through the app's UI yet.
