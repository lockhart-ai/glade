Glade 0.11.0 adds plugins: small web pages that sit beside the terminal and watch your tasks, starting with Nekomata's
cat cafe.

## New

- **Plugins.** A plugin is a folder in `~/Library/Application Support/glade/plugins/` with a `manifest.json` and a web
  page. Glade finds it, checks it, and shows it in the bottom bar beside the terminal. Settings › Plugins lists what's
  installed, with a switch for each and **Open plugins folder**; a broken plugin is listed with the reason.
- **Sandboxed.** Each plugin runs in its own process with no access to your files or Node, no network except localhost,
  and no way to navigate or open windows. It gets task and agent events (titles, states, a one-line summary of each
  tool call, subagents, questions and permission requests), never the chat, tool output or file contents. The format
  is `docs/plugin-api.md`, version 1.
- **The split.** Drag the handle between the terminal and the plugin; the width is remembered. Glade's menus, dialogs
  and toasts are never hidden behind a plugin.
- **Nekomata.** Nekomata (https://github.com/lockhart-ai/nekomata) now has a Glade build: each task is a cat, each
  subagent a kitten, and a cat raises its paw when the task needs you. To install it, build it with `./build.sh glade`
  and copy `dist/glade/nekomata` into the plugins folder. (Until its PR lands, that's on Nekomata's `glade-plugin`
  branch.)

## Running it

- **Requirements:** a Mac with Apple silicon, logged in to [Claude Code](https://docs.claude.com/en/docs/claude-code).
- **Auth:** Glade runs on your own Claude Code login (or `ANTHROPIC_API_KEY`, if you have one set). It never asks for or
  stores your credentials.
- **Install:** download `Glade-0.11.0-arm64.dmg` below, open it and drag Glade to Applications. Your workspaces and
  tasks from 0.10.0 carry over.
- **First launch:** Glade isn't notarised by Apple yet, so the first time, right-click Glade in Applications and choose
  Open (on newer macOS, if there's no Open button, click Open Anyway in System Settings → Privacy & Security). If macOS
  still won't open it, run `xattr -dr com.apple.quarantine /Applications/Glade.app` and try again.
- **Logs:** `~/Library/Logs/Glade/main.log`, one JSON line per event, rotated at 5 MB. They stay on your Mac;
  attach them to a bug report if you like (`docs/logs.md` says what's in them).

## Calls made without Jared (please review)

- A newly found plugin starts enabled, and only one plugin shows at a time. (planning)
- Plugins can send back only `ready` and a short header status; they can't command Glade. (planning)
- Nekomata's CPU, GPU and Docker readings stay empty inside Glade. (planning)
- A folder in plugins/ with no manifest.json is listed as invalid. Hidden entries, plain files and dangling symlinks are skipped. A plugin folder that is itself a symlink is accepted, but its entry and icon must resolve inside it. (#181)
- Icons over 256 KB, or a .png that isn't a PNG, make a plugin invalid, as does a manifest over 64 KB. (#181)
- Plugins are sorted by folder name. A newly found plugin starts enabled. Glade rescans the folder each time Settings › Plugins opens. (#181)
- "Open plugins folder" opens the folder in Finder. (#181)
- Plugin pages load through a custom `glade-plugin://<id>/` protocol scoped to the plugin's folder, not `file://`. Each plugin gets an in-memory session, so its storage doesn't survive a relaunch. (#182)
- A plugin can't navigate anywhere, even to its own other pages. Messages over 16 KB, or beyond a burst of 50 and then 20 a second, are dropped. (#182)
- The status dot uses the teal token (the design's green isn't a token). A plugin's page doesn't start until its card is first shown. (#182)
- The pop-out button in the design isn't built. (#182)
- Plugins get a one-line summary per tool call (Bash command, file path, search pattern, URL, query), cut to 200 characters, as plugin-api.md specifies and as Nekomata's bubbles need. A Bash command that contains a secret would reach an enabled plugin. (#184)
- Other tools (MCP tools, Glade's own, TodoWrite) send an empty summary. A subagent's `latest` is its last note or call, never a result. (#184)
- The snapshot leaves out done tasks, pinned or not. Events for tasks the plugin doesn't know should be treated as new. (#184)
- The plugin card is at least 280px wide and the terminal keeps at least 360px; the default is 680px. One width is shared by all plugins. (#183)
- The plugin view hides only while a menu, popover, dialog or toast actually overlaps it (with a 48px margin for shadows), so it doesn't blink on every right-click elsewhere. (#183)
- a working task's cat types, and switches to coffee after a call runs over 45s. Paused, or waiting on background subagents, is coffee; waiting or error is asleep. The paw goes up only for a question or permission request. (#185 (Nekomata))
- Finished kittens chase yarn for 5 minutes, then leave. The chalkboard lists running Bash commands. CPU, GPU and Docker stay empty inside Glade. (#185)
- The Nekomata e2e spec runs only when NEKOMATA_PLUGIN points at a built plugin, so it's skipped in Glade's CI. (#185)
