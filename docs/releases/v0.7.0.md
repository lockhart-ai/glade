Glade 0.7.0 is about the app around your tasks: more than one workspace, a real menu bar, Settings, and shortcuts you
can change.

## What's new

- **Several workspaces.** Click the workspace at the top of the sidebar to open the switcher: every workspace, with its
  root folder and whether it's idle, has tasks active or needs you. Switching is instant and brings back the task you
  had open there, and tasks in the other workspaces keep running and notifying; clicking a notification takes you to
  its workspace and task. New workspace… (⌘⇧N) and Open folder as workspace… (⌘O) add one, ⌘1 – ⌘9 switch between
  them, and the switcher also opens Workspace settings… and reveals the root in Finder.
- **The menu bar.** Glade, File, Edit, View, Workspace, Task, Window and Help. The Workspace menu switches, adds,
  renames, re-roots, closes (⌘⇧W) and removes workspaces; Remove from list… asks first and never touches the folder.
  The Task menu has the selected task's actions, as its right-click menu does. View toggles the panels, and File has
  New task (⌘N) and Close (⌘W, which closes the file tab you're in, or the window).
- **Settings.** ⌘, opens Settings as a modal. Agent sets the model, effort, status summary and task titles for new
  tasks; Notifications turns notifications and their sound on or off; Keyboard lists every shortcut; and the workspace's
  own section renames it and changes its root folder. Every change saves as you make it.
- **Shortcuts you can change.** Every shortcut in the keymap works (the terminal's arrive with the terminal),
  including the new ⌘P (jump to task), ⌘L (focus
  the input), ⌥↓ / ⌥↑ and ⌘⌥↓ (the next task that needs you) and ⌘⌥1 – ⌘⌥5 (the right panel's tabs). In Settings ›
  Keyboard, click a shortcut and press the new keys; Reset puts the default back. Keys another shortcut already has, or
  that macOS keeps for itself, are refused with the reason. The menu bar and the right-click menus show the keys as
  they now are.

Collapsible panels (⌘B, ⌘⌥B and ⌘J) arrived early, in 0.6.0, and are part of this phase too.

Also in this release: the chat stays pinned to its latest message when the window or its panels shrink, rather than
sometimes letting go of the bottom.

## Running it

- **Requirements:** a Mac with Apple silicon, logged in to [Claude Code](https://docs.claude.com/en/docs/claude-code).
- **Auth:** Glade runs on your own Claude Code login (or `ANTHROPIC_API_KEY`, if you have one set). It never asks for or
  stores your credentials.
- **Install:** download `Glade-0.7.0-arm64.dmg` below, open it and drag Glade to Applications. Your workspace and tasks
  from 0.6.0 carry over.
- **First launch:** Glade isn't notarised by Apple yet, so the first time, right-click Glade in Applications and choose
  Open (on newer macOS, if there's no Open button, click Open Anyway in System Settings → Privacy & Security). If macOS
  still won't open it, run `xattr -dr com.apple.quarantine /Applications/Glade.app` and try again.

Not in this release: the terminal and plugin panels, and the General, Appearance and Plugins settings. Those come in
later phases.

## Calls made without Jared (please review)

- **Tested with a scripted agent only.** Workspaces, the menu bar, Settings and the shortcuts have been exercised
  against Glade's scripted fake agent and sample data in the tests, not a real model. The menu bar's keys can't be
  pressed from a test, so the tests choose its items instead, which run the same commands.
- **Collapsible panels.** There's no design for the collapsed states: the task list hides completely, with a "Show
  task list" button in the task header, and the bottom bar folds down to its tab row. Tooltips read "Label (⌘X)", and
  the room left for the traffic lights is an estimate. ⌘F with the task list hidden shows it again and focuses search.
- **Workspaces.** They're listed, and numbered for ⌘1 – ⌘9, in the order you made them. A workspace's status is "N
  needs you" if any task needs you, else "N active", else "idle", and its badge colour comes from its place in the
  list. New workspace… and Open folder as workspace… both open the same folder dialog. Only the selected task is kept
  per workspace; the task list's filters and collapsed sections are shared.
- **Settings.** General, Appearance and Plugins are empty for now (there's no design for their contents). Ask first
  and Allow edits show but are disabled. Status summary and Task titles apply to sessions started after the change.
  Changing a workspace's root folder doesn't move sessions already running there, or write a starter CLAUDE.md.
- **Menu bar.** Close workspace shows the other workspace you opened most recently (the first-run window if there's
  none), and a relaunch remembers that. Remove from list… deletes the workspace's tasks from Glade after asking; the
  folder stays. ⌘W closes the focused file tab (or terminal tab, once there is one), and otherwise the window. ⌘,
  sits on both Settings… and Workspace settings…, and both open Settings. New task is under File.
- **Keymap.** Keys another shortcut already has are refused with the reason under the row; there's no swapping. Keys
  macOS or the menu bar keep (⌘Q, ⌘W, ⌘H, ⌘M, ⌘Tab, ⌘Space, ⌘Z, ⌘X, ⌘C, ⌘V, ⌘A and the like) can't be taken, and
  a few keys are fixed: ⇧↵, ⌃C, moving through menus, and 1 – 9 in a question card. ⌘⌥↓ goes to the next task that
  needs you, wrapping round, and ↵ sends only when pressed on its own.
- **⌘P (Jump to task)** focuses the task search, as ⌘F does, since there's no design for a jump palette. Please
  confirm that's what you want, or whether it should be dropped.

## Please check by hand

These need a visible window or the real system, so the tests can't cover them:

- **⌘W** in the Files panel closes the file tab, and anywhere else closes the window (the menu bar's Close Window).
- **Recording a menu bar key** in Settings › Keyboard (for example pressing ⌘⇧D, which Mark done has) shows the
  conflict without also marking the task done.
- **Real notifications:** a reply in a task you aren't viewing, in this workspace or another, shows a macOS
  notification, and clicking it opens that task.
